# 翻译与审阅

## 先建立完整上下文

读完整篇文章、标题层级、相关定义及关键示例，再逐段翻译。
从 PO 迁移时，按原文文件和位置把候选译文映射回文章；
缺失、模糊或过期条目重新翻译，不能把条目串接当作完整译文。
不要默认复制所有英文文件再将“目标文件存在”作为完成条件。

优先在独立草稿中完成一篇，再写入可构建的中文镜像。
超长手册可按完整小节处理，但每批需带上术语表、章节结构和前后定义。
不能为了批次大小截断句子、表格或 directive。

## 忠实度核对

逐段对照以下信息，不得在润色时省略：

- 主体、动作、对象以及条件、例外、否定、因果关系。
- must、should、may、can 的约束强度；“必须”“应当”“可以”“能够”不能随意互换。
- 默认值与可选值、支持与实验支持、主机与客户机、构建时与运行时的区别。
- 数值、单位、版本、位宽、偏移、范围、公式和错误返回语义。
- 所有列表项、注释、警告、表格单元格、示例和脚注。

可以拆分英文长句并调整语序，但不得添加原文没有的实现原因或建议。
发现原文疑似技术错误时记录问题；确需修正文档结构或链接时，
将上游源文修复与翻译清楚区分，不在译文中悄悄改变技术结论。

示例（假设项目已确认 buffer 的译名）：

> The buffer must not be reused until the operation completes.

可译为：“操作完成前，不得复用该缓冲区（buffer）。”
不能译为：“操作完成后，建议复用缓冲区。”后者既弱化约束，也改变了意思。

## 保护语法而非盲目保护版式

保留代码、命令输出、标识符、directive 名及选项、替换定义的键、显式标签、
引用目标、图片路径、章节层级和顺序。Markdown 的围栏、链接目标同理。
保留许可证、版权、作者、原始提交主题和参考文献的可追溯性。

`::` 或代码字体不一定代表可执行代码。手写寄存器说明、字段表和 ASCII 图中的
自然语言仍需翻译；偏移、位字段、常量、连接关系及示例代码保持不变。
区分手写说明与从源码生成的内容，后者按任务约定保持英文。

对需要翻译的字面量块逐块审阅，记录原文和译文摘要值及理由；
不能豁免整个文件的代码保护。其余代码块仍应按原样比对。
不要依赖简单缩进正则划分代码与正文：制表符、引用式字面量及 ASCII 图缩进
都可能让识别范围越界，将本应翻译的多段正文误判成代码。

## 结构与显示常见问题

- 中文标题装饰线按显示宽度检查，不按字符数机械复制英文长度。
- 表格和 ASCII 图需要考虑中文显示宽度；还需浏览器验证字体下的对齐。
- 内联角色、反引号与中文标点相邻时检查实际解析结果，必要时使用 RST 要求的空白。
- 普通文字中的 `CONFIG_` 等含下划线标识用字面量保护，避免意外引用。
- 不将原始英文链接、显式锚点或标签改成中文；翻译的是显示文字。
- 原文缩进错误可能把说明吞入代码块。先确认解析结果，再做最小源文修复，
  同步译文并重新生成基线，不能通过忽略警告掩盖问题。

## 完成证据

1. 文件清单：应译、已初译、已审校、生成内容、范围外内容分别可追踪。
   包括手写 `.rst.inc` 等 include 文件，以及文档树外的相关手册。
2. 内容覆盖：每个小节、列表和说明均有对应译文，不以“含中文字符”判定完成。
3. 术语一致：符合项目术语表；所有采用中文的专业术语附英文原名。
4. 结构不变量：代码、引用目标、图片、章节及源文链接经过比对。
5. 渲染抽查：首页、深层页面、复杂表格、搜索与英文入口实际可用。
6. 残留扫描：在渲染正文中找长英文段落和中英混杂半译句，逐条判断；
   排除预期保留的术语、代码、引用与生成内容，不能盲目追求零英文。

记录实际执行的检查及遗留问题。覆盖全量文件的初译与逐篇人工审定是不同状态。
